Browser PDF Extraction

This two-page fixture is original documentation for the OCR-TTS Reader test suite. It is not copied from another project, so the repository can commit it without a third-party license question.

LiteParse reads the PDF text layer in spatial reading order. It turns paragraphs into Markdown, keeps headings as headings, and leaves the original page boundaries to the caller. “Curly quotes” and other typographic punctuation should survive extraction.

What the extractor should preserve

  • Headings and their hierarchy.
  • Paragraphs with ordinary punctuation.
  • Lists such as this one.
  • Tables with a header row and body rows.
  • Inline code and fenced code blocks.
  • Hyperlinks when link extraction is enabled.

Second Page

The second page exists so integration tests can verify that page arrays stay aligned with physical PDF pages. It also gives the parser a chance to reset headers, spacing, and list state across a page boundary.

Example pipeline

const analysis = await parser.isComplex(bytes);
const flagged = analysis.filter((page) => page.needsOcr);
const result = await parser.parse(bytes);
const pages = result.pages.map((page) => page.markdown);
